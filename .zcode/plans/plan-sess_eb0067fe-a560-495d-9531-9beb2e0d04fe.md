# RP2 提示与重试协调：最小重规划

## 当前结论

RP2 的排空预算、清理重试、保存确认及正常更新顺序已获得独立认可，但最终审查仍发现两项阻断：

1. **提示未回答时，再次启动应用可绕过提示退出。** close/quit 有提示守卫，second-instance 使用的重试入口没有。
2. **连续两次退出失败会丢失第二次“继续等待”选择。** 提示内部递归调用重试时，上一轮仍持有重试标记，导致用户选择被拒绝后丢弃。

RP2 已完成两次返工，因此本次新建关联任务 **`DSK-004-RP2-ownership-01`**，保留原 `rework_rounds: 2` 和最终 REPLAN 历史，不隐形重置为第三轮修补。

## 修复方法

仅在现有 `createExitCoordinator` 内统一调度，不增加新运行时模块：

- 使用**一个非递归调度流程、一个当前尝试、一个所属提示、最多一个待消费的用户重试决定**。
- close、quit、second-instance 和更新入口共享准入规则。提示仍挂起时，外部请求只被拦截，不能启动或积压新的退出尝试。
- 提示答复只记录决定，不直接调用重试。当前尝试和提示收尾后，调度流程消费一次有效 retry，再开始下一次排空和最终动作。
- 提示取消或抛错时保留 BLOCKED、窗口锁定和未授权状态，不自动重试、不恢复已停服务的编辑能力。
- 先检查尝试/提示归属，再修改状态；旧答复、旧 finally 或迟到 updater error 不得撤销新授权或触发额外动作。
- 更新失败后的重试仍只执行普通关闭，不再次安装；`prepareUpdateExit()` 不能把后续普通关闭成功误报为更新安装许可。

## 验收

1. **提示挂起竞争**：首次最终动作失败后挂起提示，逐一及混合触发 close、quit、真实注册的 second-instance 入口。答复前 drain/finalize 保持1次，提示只有1个；答复 retry 后只新增一次尝试。
2. **连续失败重试**：最终动作前两次失败、第三次成功；用户两次选择 retry，准确得到一次保存确认、两次提示、三次排空和三次最终动作，无递归自等待或丢失答复。
3. **取消与提示错误**：第一、第二次提示分别取消或抛错，保持锁定 BLOCKED，无自动追加动作；提示结束后新的外部重试仍可用。
4. **旧回调隔离**：旧提示收尾、重复入口、迟到 updater error 与新尝试交错，不撤销新授权、不重复提示或最终动作。
5. **更新回归**：保留真实 SQLite 关闭先于 fake install 的验证；正常更新、同步失败、异步失败均正确，失败后安装次数不再增加，不执行真实更新。
6. **桌面回归**：新构建产物上 files、storage、退出桌面脚本通过；Phase C 的插桩/CDP证据与 Phase D 的自然退出分别表述，模拟对话框不冒充人工原生验收。
