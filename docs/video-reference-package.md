# 视频与提示词参考包：功能规格

> 状态：规划，尚未实现或运行验证。范围变更编号 REF-01。
>
> 首发包含通用、规则生成的提示词与单镜头参考包。AI 文案润色、MiniMax/Seedance 专用适配、外部平台自动上传及生成 API 不在本次首发承诺内。
>
> 配套：[产品计划](../plan.md)、[任务清单](ai-development-tasks.md)、[排期](development-schedule.md)、[项目评估](../项目评估.md)。源码基线 `eee9234`，代码位于原 DirectorDesk 目录；新仓库目前仍是文档仓库。

## 1. 功能目标和范围

用户完成镜头预演后，一次获得与实际导出片段对应的视频、首尾帧、生成提示词和素材清单，再自行上传到支持相应输入的外部生成平台。

产品流程：AI 设计镜头 → 局部修改 → 填写成片设定 → 确认导出范围 → 检查提示词 → 下载参考包 → 在外部平台生成。

价值不是新增普通文本框，而是明确回答：这份提示词对应哪个场景、哪个机位、哪段时间、哪一版视频；工程变更后是否需要更新。

### 1.1 首发包含

- 当前戏段、明确摄影机、单连续镜头的指定时间范围。
- 同一冻结快照生成视频、首尾帧和镜头事实描述。
- 中文通用提示词，用户可编辑外观与风格、手动修订文稿。
- 工程内时间到片段内时间换算、过期检测与重新生成。
- ZIP 打包、文件哈希和可读使用说明；普通视频和工程下载保留。
- 明确标注通用输出未验证任何特定模型的输入兼容性。

### 1.2 后置

自动多镜头拆包、整场批量参考包、关键帧联系表、角色参考图自动打包、AI 文案润色和翻译、深度/姿态/分割通道、自动云上传、外部视频生成 API、云转码。

“SD 2.0”暂不映射为某个模型：若指 Seedance 2.0，须确认实际平台/版本/入口；若指 Stable Diffusion 2.0，不能当作原生视频参考生成模型。MiniMax 也须具体到产品、模型版本、地区和网页/API入口。本规格没有对这些能力进行在线核验。

## 2. 现有基础与复用边界

`src/production/bundle.ts` 已存在 `productionEntries()`，能够打包工程、当前戏段参考图、逐场已保存提示词、素材对应关系、剧情台词和可选视频。现有使用说明明确提示：修改编排后需要手动同步提示词。

已发现的相关边界：

- 已保存逐场提示词可来自多个戏段，但视频及部分素材属于当前戏段。
- 当前包中可选视频文件名固定为 MP4，不能直接套用于网页 WebM 回退。
- `project.references` 是已有参考图，不等于从实际导出视频采样的首尾帧。
- 工程格式、旧 ZIP 及旧提示词保留兼容；新功能建议使用独立 `reference-package` 导出类型，不静默改变旧包语义。

复用已有 ZIP 工具、视频编码、模板工程和纯类型；新增范围归一化、事实提取、成片设定、提示词版本和新 manifest。现有存储文稿只能作为 legacy/manual 输入，不声称它已与新导出范围同步。

## 3. 界面与状态

入口：导出 → AI 视频生成参考包。

步骤：

1. 选择当前戏段和摄影机，显示范围及画幅。节目输出在范围内无切换时可解析为单一摄影机。
2. 输入起止时间，显示归一化后的有效范围与实际时长；默认5—15秒，不能静默裁剪。
3. 填写或复用“成片设定”：角色外观/服装、环境材质/时代、视觉风格、期望灯光。缺省不自动虚构。
4. 本地生成提示词，显示事实区、外观风格区、用户附加区和警告。
5. 检查是否过期或有人工改写，确认后导出；重复下载不调用模型、不扣额度。
6. 完成后显示“已生成并发起下载”，不能声称文件已落盘。

状态：未生成、已同步、已人工修改待确认、已过期、资料不完整、生成中、打包中、失败、下载已发起。

生成中锁定同一文档写操作，保留取消按钮；失败必须释放锁并恢复预览状态。多标签页不共享隐式锁：以各自冻结快照和明确来源导出，不允许从另一标签页更新一半资料。

## 4. 导出文件约定

示意目录（格式由实际编码结果决定）：

```text
shot-001-reference/
  preview.mp4              # 实际选择WebM时为preview.webm，二者只出现一个
  first-frame.png
  last-frame.png
  prompt.txt
  reference-guide.md
  manifest.json
```

不默认携带完整 `.director` 工程，避免把无关戏段和资源一并传给外部平台；工程备份用独立入口。包只包含所选范围的成品素材，不包含密钥、对话历史、本机路径、账号邮箱和支付数据。

| 文件 | 要求 |
|---|---|
| 视频 | 实际容器、codec、宽高、帧率、帧数、时长写入manifest |
| 首尾帧 | 来自视频输出同一采样序列的首张/末张输入画面，不是工程全段首尾 |
| prompt.txt | UTF-8；与该范围绑定；含通用参考说明、事实描述与成片设定 |
| reference-guide.md | 素材用途、上传前检查、目标入口未验证的提醒、无声预演说明 |
| manifest.json | 版本、来源、实际范围、文件映射、哈希、文稿来源与同步状态 |

如视频编码失败，不生成假装完整的参考包；可以选择单独下载文稿/工程，但不得标为参考包成功。首尾帧或哈希失败同样阻塞完整包。ZIP路径使用经过净化的固定相对路径，不采用任意用户输入路径。

## 5. 时间和画面一致性

### 5.1 采样规范

首发固定整数输出帧率24fps，不隐含支持所有VFR/小数帧率。用户输入范围为 `[requestedStart, requestedEnd)`，归一化为输出帧网格：

- `startFrame = ceil(requestedStart * fps)`；
- `endFrameExclusive = floor(requestedEnd * fps)`；
- `frameCount = endFrameExclusive - startFrame`，必须大于0；
- `effectiveStart = startFrame / fps`；`effectiveEnd = endFrameExclusive / fps`；
- 第k帧的工程时间为 `(startFrame + k) / fps`，输出PTS为 `k / fps`，每帧持续 `1 / fps`。

边界计算需处理浮点误差（例如帧号附近1e-6容差），避免本应落在网格上的时间被误移一帧。UI在确认前展示有效范围；归一化后不足支持的时长要求用户调整，不自动凑时长。

最后一帧工程时间为 `(endFrameExclusive - 1) / fps`，不是 `effectiveEnd`。禁止采样结束点以免混入下一镜头。manifest同时记录请求范围、有效范围、帧数与末帧时间；编码器帧调度须与本规范统一，不保留另一套独立取整逻辑。

示例：请求工程12—20秒、24fps，输出192帧，工程首帧12秒、末帧19.958333…秒，视频时长8秒。提示词时间均在片段0—8秒内。

### 5.2 镜头和事件处理

- 单一摄影机导出忽略节目切换，manifest标明 `cameraMode: explicit`。
- 节目输出 `cameraMode: program` 若有效范围内部发生摄影机切换，则首版拒绝并要求选择单一机位或缩小范围；起点恰在切点采用切点后的摄影机，终点切换不在范围内。
- 人物动作与范围求交，片段内时间为工程时间减effectiveStart；起点前已开始的动作写“片段开始时正在…”，不重复起步。
- 不在片段内发生的动作不生成；跨界事件记录裁剪来源，不截断成错误因果。
- 相机左/右不能直接用世界X轴正负替代。先描述工程坐标关系；屏幕方位需要该机位投影可确定才生成，不能确定则省略并警告。
- 暂不能可靠推断的复杂骨骼动作使用保守名称或标记需补充，不把模型文件名自动写成具体情绪/剧情。

视频和帧使用同一渲染配置，排除编辑器UI、选择框、轨迹线等辅助层。材质效果、画幅和机位必须一致。可通过解码视频首尾帧做有损容差比较，不要求PNG与有损视频字节一致。

## 6. 镜头事实与成片设定

### 6.1 规范化事实

建议纯数据 `ShotFacts`，包含场景/摄影机ID、有效范围、输出采样、角色列表、动作/路径事件、机位运动、已知光照描述、来源与提取器版本。不上传完整工程给模型做二次视频识别。

事实根据导出时当前工程重新计算，不只复用此前AI任务的计划，因为用户可能已经手动编辑。

成片设定单独保存：角色ID→显示别名/外观、场景外观、风格、声音意图、附加约束。白模肤色、模型默认服装不自动成为成片身份。外部参考图尚未打包时不得输出“见图1”等不存在引用。

### 6.2 提示词编译规则

确定性中文模板包含：

1. 目标时长与视觉风格（有输入时）。
2. 素材用途：视频用于构图、走位和运动参考，不代表所有平台支持上传。
3. 场景与角色设定（未知部分省略或在界面提示补充）。
4. 按片段相对时间排序的摄影机与人物安排。
5. 连续性约束和适用的排除要求。

音频：预演视频无声；用户输入对白只能列为期望，不声称视频已有音轨或目标模型一定支持音频生成。没有明确设置不虚构对白、声音、服装或剧情。

“不要白模、不要辅助线”等通用文字可作为成片期望，不声称所有模型有单独negative prompt字段。

### 6.3 示例（人工设定的测试场景）

以下只是通用文稿示例，不是MiniMax或Seedance已验证专用语法：

```text
目标：生成8秒写实剧情视频。
素材用途：如目标入口支持视频参考，请将preview.mp4用于参考机位、人物走位和节奏；角色外观与环境材质以以下成片设定为准。
场景设定：夜间医院走廊，冷白顶灯，浅绿色墙面。
角色A：穿深灰风衣的年轻女性；片段开始时位于前景，背对摄影机。
角色B：穿黑色夹克的成年男性；位于走廊另一端，面向角色A。
0—3秒：摄影机从角色A身后缓慢推进，两人保持位置。
3—5秒：角色B后退两步，角色A保持原位。
5—8秒：角色B停下，摄影机继续缓慢推进。
保持同一连续镜头，不新增人物或额外切镜。成片不保留白模材质和编辑器辅助标记。
```

“后退两步”仅可来自已确认的动作语义或人工设定；纯位移轨迹只能证明移动，不能可靠推断步数。

## 7. 版本、过期与人工修改

### 7.1 快照与哈希

以冻结导出快照为一次事务来源。`sourceSnapshotHash`覆盖当前戏段全部可能影响渲染的状态、相关资源内容标识及引擎版本；保守地对当前戏段变化标过期，比漏掉父节点/灯光/纹理影响更安全。

`promptInputHash`覆盖ShotFacts、角色映射、成片设定、有效范围、输出采样、目标适配配置、编译器版本。稳定序列化规则固定键序和数值表示，排除编辑器选区/播放头/纯UI状态。

提示词文本另存 `promptContentHash`。实际文件哈希用于完整性，不代表下游生成结果可复现；模型随机性不由本包保证。

### 7.2 更新与冲突

- 事实/范围/机位变化：旧提示词标过期，参考包导出前必须重建或明确确认重新绑定。
- 只改用户附加文字：标记人工修改，保留可对照的规则生成底稿。
- 自动更新不能覆盖人工修订；展示差异后由用户选择重新生成或确认自定义文本。
- 人工文本可能与事实冲突。软件可对已知字段做检查，但不承诺完整语义验证；manifest使用 `manual_confirmed` 并在说明中标注人工确认，不写成机器已验证一致。
- 编译器/适配配置升级：标为需要重新检查，不在下载按钮中静默触发收费模型任务。
- 旧项目已保存逐场提示词：导入为 `legacy_unbound`，保留原文；在用户绑定范围并确认之前不标“已同步”。

冻结快照后，视频、帧、文稿和manifest必须来自同一版本。取消打包释放临时Blob和渲染锁；再次导出可以复用未过期文稿，不必须复用视频字节。

## 8. manifest字段契约

格式名建议 `director-video-reference-package`，首版version=1，与旧素材包manifest分开。以下为待实现schema，不是现有API。

| 字段 | 约束 |
|---|---|
| format/version/packageId | 固定格式、整数版本、包实例ID |
| source | 本地documentId、sceneId、cameraMode、cameraId、sourceSnapshotHash、engineVersion |
| range | requestedStart/End、effectiveStart/End、endExclusive=true |
| sampling | fps=24、frameCount、firstSampleTime、lastSampleTime |
| video | file、container、codec、width、height、duration |
| frameReferences | first/last文件、frameIndex、sourceTime、outputTime |
| prompt | file、language=zh-CN、mode、promptInputHash、promptContentHash、compilerVersion、userConfirmedAt |
| target | adapterId=generic-v1、verificationStatus=generic-unverified、entryPoint=null |
| characters | entityId、alias；不包含账号和本机绝对路径 |
| warnings | 缺失外观、未知动作、人工改写、未验证目标入口等 |
| files | manifest以外每文件的相对路径、MIME、字节数、SHA-256 |

manifest不把自己的哈希写进自身，避免自引用；ZIP可另显示下载整体校验值但首版不要求。所有文件引用必须存在，MIME/扩展名匹配实际输出；字符别名冲突在导出前提示。

## 9. 模型适配与使用说明

首版只提供 `generic-v1`，不显示“MiniMax视频参考已支持”或“Seedance已验证”。用户仍可手动将通用文本/图像用于合适入口，但软件不保证可上传视频。

后续适配配置必须记录：provider、产品/模型版本、网页或API入口、地区、输入类型、时长/大小/格式限制、引用语法、负向字段/音频能力、来源URL、检查日期、实际测试状态。能力未知使用null，不默认true。

| 入口已验证能力 | 交付说明策略 |
|---|---|
| 视频参考 | 指定视频用途和上传位置 |
| 首帧图生视频 | 用first-frame和文字，不要求上传视频 |
| 首尾帧 | 使用first/last；说明末帧来自最后实际输出帧 |
| 仅文本 | 只用文字，提醒不能直接利用预演视频约束 |
| 未验证 | 展示中性说明，不猜上传槽位或引用token |

用户下载后的外部传输由用户操作；本功能不调用平台上传，不自动带入账号或Cookie。将来验证MiniMax/Seedance需先获真实模型调用预算并固定测试版本；未通过不影响通用包验收，但不允许专用宣传。

## 10. 计费、隐私和扩展

首发事实提取、规则文稿、手动编辑、ZIP打包、重复下载全在本地执行，不消耗AI额度，不访问云AI。已有AI镜头设计仍按原计划收费。

AI文案润色作为后续候选，不纳入新增9人日；如果启用，复用现有任务/账本，不新造计费链。输入必须最小化为ShotFacts与成片设定，经明确确认后上传；按用户隔离缓存，重新下载同结果不扣费。润色不得改写事实字段，模型不得执行工程工具。

分析事件建议新增 reference_package_requested、reference_prompt_regenerated、reference_prompt_stale、reference_package_ready、reference_package_failed；不上传提示词正文、角色外观、视频或工程哈希到第三方分析服务。包成功是“文件生成并发起下载”，不是“外部成片已成功”。

## 11. 验收用例

以下REF用例单独计数，不替换原50+10的AI镜头评测集。规则用例要求全通过，失败影响对应发布门禁。

| ID | 场景 | 预期 |
|---|---|---|
| REF-T01 | 导出12—20秒 | 相对0—8秒、192帧、末帧19.958333…秒 |
| REF-T02 | 非网格起止 | 展示归一化范围，帧数/视频/提示词一致 |
| REF-T03 | 空/倒置/不足范围 | 拒绝，无空包、不扣费 |
| REF-T04 | 动作从范围前开始 | 描述为正在进行，不重复起步 |
| REF-T05 | 动作在范围后发生 | 不出现在本段提示词 |
| REF-T06 | 内部切镜与显式机位 | 节目多切换拒绝；显式机位正确忽略切换 |
| REF-T07 | 结束点恰有切镜 | 不采下一镜头画面 |
| REF-T08 | 改机位/人物/灯光/资源 | 旧包源与提示词标记过期 |
| REF-T09 | 只移动播放头 | 不导致文稿过期 |
| REF-T10 | 旧提示词/人工改写 | 原文保留，未绑定不假报同步，更新需确认 |
| REF-T11 | 未填写角色外观 | 不编造服装、脸型或身份 |
| REF-T12 | 未知/复杂动作 | 省略或标记需补充，不虚构步数和剧情 |
| REF-T13 | WebM回退 | 文件名/MIME/manifest/使用说明全部对应WebM |
| REF-T14 | 取消/编码失败/帧提取失败 | 无完整成功包，释放锁，工程可继续编辑 |
| REF-T15 | 文件完整性 | 全部引用存在、哈希可复算、无自引用哈希 |
| REF-T16 | 冻结后工程或标签页变化 | 同包不混入新状态，来源可识别 |
| REF-T17 | 首尾帧与视频 | 同一采样、无辅助线；有损比较采用合理容差 |
