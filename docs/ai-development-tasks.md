# AI 开发任务清单：商业网页版

> 状态：全部未开始。与 [plan.md](../plan.md) 配套，基于 `eee9234`；此文不是自动开工授权。排期见 [development-schedule.md](development-schedule.md)。
>
> 工作量单位为人日，1 人日约 6 小时有效工程工作，含 AI 生成、人工审阅、单测及局部返工；不是模型运行时长。总计 66 人日，另预留集成与发布缓冲。

## 1. 执行规则

1. 先确认计划；在非默认业务分支开发。没有明确授权不提交、推送、购买、部署或触发真实付款。
2. 每次 AI 编码只执行一个任务或一个经过批准的小子任务。依赖未满足时只可实现契约或 mock，并写明阻塞，不能伪报完成。
3. 开始前读根 `plan.md`、本任务、适用 `AGENTS.md`、涉及文件和当前 git diff。不得覆盖未归属自己的修改。
4. 保留现有 Vite/DOM/Three.js 核心；不要自行换 React、重写渲染器或升级全量依赖。
5. 新增路径是建议，开始实现时记录实际路径；不为满足计划机械创建空目录。
6. 默认测试使用 mock 模型、支付沙箱和本地数据库。真实模型评测需明确预算，禁止调用任意工程中发现的密钥。
7. 准备证据：改动文件、执行命令、输出结果、失败项、人工验收步骤及遗留风险。未执行必须写“未执行”。
8. 任务交接后由人审核，才将状态改为完成；AI 不自行批准上线。

## 3. 基础与交互任务

### WEB-001：环境、源码和测试基线

- 输入：当前仓库、package.json、Node 环境、现有测试；不默认已有 node_modules。
- 动作：记录 HEAD、工作区、工具版本；经允许安装锁定依赖后执行 `npm test`、`npm run build`；阅读 `scripts/smoke.mjs` 再决定运行前提。
- 产物：`docs/implementation/baseline.md`（拟新增），已存在失败与新回归分开列出。
- 验收：能够启动浏览器编辑器，记录实际端口/浏览器；如果基线失败明确阻塞，不修无关问题。

### WEB-002：产品范围、外部服务与计费决策

- 与负责人确认销售地区、主体、品牌候选、模型、邮件、支付、托管、任务预算；记录 ADR 和费用权限，不提交真实凭据。
- 固定首版“30 天额度包，不自动续费”“工程本地”“交付有效提案计费”的语义。
- 产物：`docs/implementation/decisions.md`，服务供应商能力、沙箱/生产条件及负责人签字状态。
- 验收：每项要么批准，要么有明确阻塞与 mock 路径；没开户不标作支持真实支付。

### WEB-003：网页/桌面 AI 传输抽象

- 涉及：`src/ui/ai-panel.ts`、`src/automation/desktop-types.ts`、拟新增 `src/web/ai/transport.ts`。
- 将界面和 Electron bridge 解耦，保留桌面 adapter；网页使用 mock adapter 先验收。
- 验收：无 `window.directorDesktop` 时可进入网页 AI 流程；桌面原渠道流程不被删除；浏览器 bundle 不包含 fs/safeStorage 或密钥。

### WEB-004：DTO、错误码和 mock 契约

- 定义任务、提案、scope、状态、额度、订单及错误；编写共享 Zod schema、样例和版本兼容规则。
- fixtures 包含成功、冲突、未知字段、超限、过期和余额不足。前后端只能导入纯 DTO，不互相导入引擎/服务实现。
- 验收：同一 fixture 可被浏览器和 Node 验证；用量/价格由客户端传入时不能影响服务端计算。

### WEB-005：品牌和简单模式界面

- 涉及：现有面板、CSS、拟新增 `src/web/onboarding/`；先识别实际入口再改。
- 默认任务式布局，五类模板入口；折叠高级属性；网页移除不可用桌面渠道/MCP配置；错误可恢复。
- 验收：1280×720 与 1920×1080 桌面窗口主要任务可用；键盘焦点清晰；高级模式仍可访问。

### WEB-006：五类参数化镜头套件

- 套件数据与生成逻辑分离，场景/角色/机位 ID 稳定；支持画幅、时长、站位和运动方向。
- 只用许可清晰的内置资源，资产清单附来源；不开发素材商城。
- 验收：五套分别能在无模型调用时实例化、播放和导出；边界参数不产生 NaN、越界时长或缺失角色。

### WEB-009：本地工程隔离、恢复与备份

- 涉及：`src/storage.ts`、`src/ui/project-save.ts`，新增品牌命名空间和 documentId。
- 记录存储 schema；区分不同登录账号的本地项目视图；退出账号不擅自删工程，提供清除入口。
- 验收：刷新恢复、存储配额不足、写入失败、标签页竞争有提示；导入旧工程可用；上游 IndexedDB 不被覆盖；“登录不等于云备份”可见。

### WEB-014：摄影机与人物简易控件

- 景别、角度、运镜、速度、时长使用确定性操作，不调用 AI；沿用同一撤销与校验管线。
- 验收：快捷修改保持无关对象不变；任务运行时写操作被锁定；结束/异常后解锁。

## 4. 服务与 AI 执行任务

### WEB-007：API、数据库和迁移骨架

- 新增独立 Node/TS 服务、PostgreSQL schema/迁移/测试配置、健康检查；同站点代理设计。
- 准备 session、task、proposal、ledger、order 的基础表；后续业务任务补约束与索引。
- 验收：新库迁移和已有库升级可重复；CI 不连接生产数据库；未配置必需变量时启动报错但不输出秘密。

### WEB-008：邮件登录与会话

- 一次性、摘要存储的短期登录 token；确认页 POST 消费，防邮件扫描器 GET 提前消费。
- HttpOnly/Secure/SameSite cookie、会话撤销、来源/CSRF校验、登录速率限制。
- 验收：重放/过期令牌拒绝，退出后会话失效，邮件失败有提示，接口不泄露账号是否存在；付费 API 不接受任意 userId 冒充身份。

### WEB-010：Provider 与有界请求适配

- 抽取桌面 provider 中可复用的纯请求逻辑，排除本地文件、Electron 和用户任意 baseUrl。
- 一个主要 provider，明确 structured output/tool schema 能力、超时、取消、token/调用预算和价格版本。
- 验收：mock 覆盖 429、5xx、无效 JSON、网络断开、流中断、usage 缺失；没有未知错误无限重试。

### WEB-011：持久任务、队列与幂等

- PostgreSQL 持久任务、worker lease/heartbeat、最大尝试；任务在服务器重启后可恢复/确定失败。
- POST 同用户同幂等键相同输入返回同任务，不同输入 409；每用户并发 1；前端短轮询。
- 初期使用仅开发环境的明确 mock entitlement；公开环境必须接 WEB-018，不能留下默认放行开关。
- 验收：两个 worker 不重复领同一任务；重启不无限卡住；跨用户读取/取消被拒；不把 AI 执行锁长期持在数据库事务内。

### WEB-012：镜头规划与确定性操作编译

- 基于模板生成受约束 ShotPlan，再编译为 `EditOperation[]`；稳定生成新 ID；不开放完整任意工具集。
- 支持创建与局部修改；读取足够当前对象数据，但不传整个无关项目和二进制。
- 验收：代表性创建/修改 fixture 可通过执行器；未知资源拒绝；模型只返回建议文字不算成功；输出 schema/template 版本。

### WEB-013：本地范围校验、提交与任务撤销

- 在现有 `createToolService` 外接网页协调层，不破坏桌面执行器语义。
- 比较 scope 允许字段、锁定对象、前后快照；预检和提交使用独立 requestId；一个任务一个提交批次。
- 验收：camera-only 不改人物；校验失败无写入；一次撤销恢复前状态；手动变更 revision 后拒绝旧提案；busy 锁异常释放。

### WEB-015：AI 前后端任务闭环

- 接登录、任务创建、进度、proposal 获取、本地执行、取消与摘要；提交任务前展示固定额度消耗说明。
- 流程不需要 Electron；已完成提案刷新可查询；上游聊天面板不承担计费业务逻辑。
- 验收：一个创建、一个限定修改走通；网络错误保留输入；双击发送不双建任务；完成后播放不自动开始下一次 AI 消费。

### WEB-016：刷新、冲突与提案恢复

- 持久本地 proposalId、前后哈希和恢复快照；区分服务器成功、本地未应用和已应用。
- 不重用旧 previewId/revision；不确定时在副本应用或保留当前工程；任务取消与刷新不重复收费。
- 验收：模拟提交前后各点崩溃/刷新；无重复人物或机位；不会用旧任务覆盖新工程；客户端 ack 缺失不触发无限退款。

### WEB-017：服务端范围验证与受控修复

- 服务端验证用户 snapshot 格式、允许编辑范围、资产 allowlist、操作上限和模型输出；与浏览器关键范围规则共用纯逻辑。
- 最多三次模型调用预算，修复不能扩大 scope；持久记录每次尝试结果，不保存敏感内容到普通日志。
- 验收：诱导执行任意代码、外部 URL、支付和跨场景删除的内容不能成为工具能力；最终失败不给成功提案，不污染工程。

## 5. 计费、导出与运营任务

### WEB-018：额度预留、结算与补偿账本

- 整数额度、不可变账本、taskId 唯一 reservation；事务性 reserve/settle/release/reversal。
- durable valid proposal 与 settle 同事务；服务端判断，不依赖浏览器报告；取消成功竞态和过期额度规则实现。
- 验收：并发不透支；重复结算/释放/补偿无第二次变动；负余额无意外产生；重试提案可重取不重扣；故障记录可对账。

### WEB-019：支付订单、通知与退款对账

- 一家获批 provider，产品价格以服务端目录为准；一次性 30 天额度包；不实现未批准自动续费。
- 验证原始请求体签名、时间窗口、订单商户/金额/币种与唯一事件；异步事件以状态机处理乱序和重复。
- 验收：伪造前端成功页不发额度；同订单不同通知不重复 grant；失败支付无权益；退款/争议有账务补偿与人工处理边界；沙箱全流程和被授权的小额生产验收分别记录。

### WEB-020：价格、权益与购买界面

- 明确额度包、有效期、无自动续费、结果交付定义、售后规则与下游模型费用不含。
- 客户端只展示服务端权益；订单 pending 状态可以刷新恢复；不以跳转参数显示支付已确认。
- 验收：余额不足、付款失败、迟到回调、有效期、补偿额度展示一致；价格必须用已批准配置。

### WEB-021：浏览器参考视频导出优化

- 复用 Mediabunny，处理 `default` 桌面保存模式、codec 能力探测、取消/进度/错误回退。
- 首测 720p/24fps/5—15s；允许 MP4 不支持时 WebM；工程下载始终可用。
- 验收：指定浏览器矩阵可播放导出文件；编码失败后工程仍可编辑；不将下载启动表述为已成功落盘；内存不足给出减规格建议。

### WEB-022：限流、数据边界与保留策略

- 限额/请求大小/并发全在服务端；会话授权、模型密钥管理、敏感日志脱敏。
- 实现 7 天内容清理任务、账号删除请求与处理记录、账务例外；仅处理被明确授权上传的规范化快照。
- 验收：过期内容删除、清理幂等、不同账号任务隔离、删除后不可继续调用；分析事件不含 prompt；服务端配置不会通过构建进入网页。

### WEB-023：指标、成本、日志与关键事件

- requestId/taskId 贯穿；模型次数、延迟、失败、有效提案成本、账本差异和队列积压可观测。
- 区分服务器 proposal_ready/payment_confirmed 与客户端 proposal_applied/export；不把后者当可信付款依据。
- 验收：一个故障任务可由脱敏日志定位；有预算/错误告警；价格版本、usage 缺失可识别；去重事件不重复计算。

## 6. 验收与发布任务

### WEB-024：AI 评测集与版本回归

- 建立 50 条固定集 + 10 条独立保留用例，覆盖创建、局部修改、失败和冲突；固定版本、参数和成本预算。
- 输出 schema 正确率、有效工程率、画面符合率、保护字段违规率、延迟和成本；保存可复查案例但不采真实客户隐私。
- 验收：有效任务成功率目标 ≥90%，保护字段违规为 0；失败不污染工程；不能用删难例或仅测模板默认输入达标。未达标阻塞公开收费。

### WEB-025：一致性、授权与账务测试

- 使用本地/授权沙箱，覆盖跨用户访问拒绝、并发余额、回调验签、重复/乱序通知、worker 重启、取消/成功竞争和过期任务。
- 验收：所有资金与授权关键用例通过，账本可重算；不以普通 happy-path 截图替代故障测试。

### WEB-026：浏览器端到端与可用性验收

- Windows Chrome/Edge、macOS Chrome，记录实际版本/硬件/网络；E2E 创建/修改/撤销/恢复/备份/导出/购买状态。
- 5 名目标创作者完成任务，观察操作卡点；画面正确性人工看真实预演，不能只检 DOM。
- 验收：至少 4/5 无代操作完成任务；固定场景性能与输出达到 plan 门槛；不支持环境提前提示。

### WEB-027：官网、样例与准确宣传内容

- 首页、价格、示例、与开源版区别、使用说明；优先静态可抓取 HTML，不让搜索引擎只能看到编辑器加载壳。
- 真实创建和局部修改演示；title、description、canonical、sitemap 与实际部署域名一致；账号/支付/私有任务页面 noindex。
- 验收：文案与已实现能力一致；不宣传一键成片/唯一/零外传；样例可下载复现；统计绑定真实漏斗事件。

### WEB-028：许可、隐私与服务说明

- 核对 MIT、资产、依赖和前端分发清单；保留上游归属；资源不是全部重新标 MIT。
- 隐私说明覆盖远程 AI、内容保留、工程本地、删除与客服；条款覆盖额度、失败、售后、非自动续费。
- 验收：负责人审核法律/地区适用性；未核实商标不作为正式上线品牌；文案不替代必要资质检查。

### WEB-029：部署、告警、备份与回退

- CI、隔离环境、同源代理、TLS、数据库备份恢复、worker 重启与预算熔断；环境变量由托管平台管理。
- 数据库迁移优先兼容性 expand/contract；旧应用回退不随意回滚已发生的账本交易。
- 验收：演练应用回退和数据库恢复；恢复账本后与支付 provider 对账，防历史事件重复发额；部署域名与地区获批准。

### WEB-030：限额内测与反馈处理

- 招募、同意、任务脚本、观察记录、问题分级；所有真实模型调用设总预算。
- 使用获批 staging/限额生产，未获支付授权不自行扣真实款。内测可先使用测试额度，不等于付费转化验证。
- 验收：形成问题清单与负责人，P0（丢工程、错误扣款、越权）为零；高影响 P1 修复或阻塞。

### WEB-031：成本、价格与收费门禁

- 汇总评测与内测成本，批准正式产品目录、额度、取消/退款边界和服务支持成本。
- 核对生产支付开户、模型条款、地区条件、告警与客服；试用滥用不会无限扩大支出。
- 验收：负责人批准限额付费试点；真实支付未验证则保持关闭，不把沙箱通过称为商业上线。

### WEB-032：发布清单与运营交接

- 发布说明、功能支持矩阵、已知问题、值守/客服责任、停止 AI 任务与停止支付入口的开关。
- 验收：基线回归、AI质量、账务、许可、隐私、恢复证据齐全；负责人明确 Go/No-Go。发布后 14 天的商业验证单独进行，不伪装成当天完成。

## 7. 给 AI 编码助手的单任务指令模板

以下为待填写的任务委派模板，不是可直接执行的 shell 命令。

```text
项目：E:\myProgram\DirectorDesk\director-desk
任务：WEB-编号（一次只做一个已满足依赖的任务）
先读：plan.md、docs/ai-development-tasks.md、本任务涉及文件与适用 AGENTS.md。
先检查 git 状态与已有实现，说明实际将改的文件，不覆盖其他任务变更。
目标：严格实现该任务的输入、输出和验收，不扩展商业模式或重写技术栈。
约束：不提交/推送/部署/购买；不使用真实密钥或付款；新依赖先说明必要性。
流程：契约/测试 → 最小实现 → 单测/构建 → 指定验收 → 交接。
结束输出：改动清单、测试命令及真实结果、未执行项、遗留风险、下个依赖任务。
若依赖不足或安全/数据/账务语义不明确，停在具体阻塞处，不自行放宽门禁。
```

## 8. 完成定义与交接

每个任务交接记录建议保存到 `docs/implementation/WEB-编号.md`，由任务完成时创建，不预先生成空文件。至少包含：

- 起止源码版本、实际改动路径；
- 实现的契约/迁移与兼容影响；
- 测试命令、执行环境、真实结果；
- 人工操作步骤与必要截图/录屏；
- 使用的 mock/沙箱/真实模型与获批费用；
- 未完成项、已知失败、负责人；
- 是否满足验收，以及人审结论。

不得只写“测试通过”而不说明测试范围；不得将客户端模型调用成功等同账务、授权和最终镜头全部正确。
